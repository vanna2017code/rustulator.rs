## the languages behind the scenes

rustulator is a simple calculator built with:

1. Rust (backend logic)
2. HTML, CSS, and JavaScript (frontend)

## contributing

this project is licensed under the MIT License. you can use, modify, and share it, including in commercial projects, as long as you include the original copyright notice and the license text. the license also comes with no warranty.

if you'd like to contribute, follow these steps:

1. find an issue. look for labels like `good first issue` or `beginner friendly` if you're new.
2. read this README and any other documentation related to contributing.
3. fork the project on GitHub to make your own copy.
4. clone your fork and move into the project folder:

   ```sh
   git clone https://github.com/vanna2017code/rustulator.rs.git
   cd rustulator.rs
   ```

5. beginner's tip: don't work directly on `main`. create and switch to a branch for your changes:

   ```sh
   git switch -c fix/short-description
   ```

6. set up the project. setup instructions in `CONTRIBUTING.md` are coming later.
7. make your changes and test them. you don't want to submit a change with bugs!
8. check `git status` to review what changed. stage only the files you intend to include, then commit with a useful message:

   ```sh
   git add path/to/changed-file
   git commit -m "Describe your change"
   ```

9. push your branch to your fork:

   ```sh
   git push origin fix/short-description
   ```

10. on GitHub, open a pull request from your fork's branch into this repository and follow the prompts. See `CONTRIBUTING.md` for more details when it's available.
11. wait for a review. if your pull request is accepted, hooray! you're a contributor.

### bonus thingy: how to become a collaborator

you can contribute without being a collaborator. but if you'd like to help more directly, collaborator access means you can work in the main repository without having to maintain your own fork for every change. it can make contributing easier if you plan to help regularly with code, issues, or pull-request reviews.

if you'd like to become a collaborator, contact me through GitHub or one of my contact details and tell me what you'd like to help with. collaborator access is by invitation: if i agree, i'll invite you through the repository's **Settings → Collaborators** page. accept the invitation on GitHub to get access. even as a collaborator, it's best to use branches and pull requests so changes can be reviewed.
